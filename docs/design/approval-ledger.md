# 承認の仕組みの設計 (案3: 引用された承認を、機械で確かめて使う)
よしひろさんの指示 (2026-11-15): 「3 (引用された承認を認める) で進めたい。そのために出てくる問題を洗いざらい出して、陥らない方法をまとめて。5回繰り返して、改善の上に改善を乗せて、誤作動しないように」。
状態: 設計の途中 (ラウンドごとに更新)。秘密・URL・ID・個人データは書かない。

## 目標
よしひろさんの手間を増やさず (許可は、モネの会話で、コピーする1文で出す)、Work が、**本人の許可の原文だけ**を根拠に、**許可された範囲だけ**を実行する。モネの写し間違い・取り違え・使い回しは、**受付の機械チェックで、Work に届く前に**止める。

## ラウンド1: 問題の洗い出しと、防ぎ方
| # | 起きうる問題 | 防ぎ方 |
|---|---|---|
| 1 | モネが原文を写し間違える・書き足す | 承認は、原文を1つのコメント (`[MONE-APPROVAL]`) にそのまま置く。対象・操作・範囲・期限は、**原文の決まった書式 (目的/対象/操作/範囲) から、機械が読み取る**(モネが別に書き直さない)。書式に合わない原文は、受付が断る |
| 2 | 承認と依頼のひも付け違い (別の対象への使い回し) | 依頼には、承認IDだけを書く。受付が、依頼の対象・操作が、承認の対象・操作と一致するか照合する。不一致は Work に届く前に断る |
| 3 | 期限の見落とし | 承認に期限は付けない (v11)。依頼に、モネの期限 (最大3日) を付ける。出し直しは最初の期限を引き継ぐ。受付と Work が、現在時刻と照合する |
| 4 | 同じ承認の二重使用 | 1つの承認IDは、同時に1つの依頼だけ。使用台帳 (`docs/special-used.md`) と受付で照合。同じ依頼IDの結果があれば実行しない |
| 5 | 承認コメントが、あとから書き換えられる・消される | 編集された承認 (`updated_at` が作成時と違う) は、受付も Work も使わない。実行の直前に、もう一度読み直して確かめる。消えていたら止まる |
| 6 | Work が複数の場所から指示を受けていて、古い決まりが残る | Work の指示の出どころを全部数える (予定タスクの指示文・土台の指示・チャットの履歴・依頼の本文)。それぞれに版の印を付け、指示文の台帳 (`docs/instructions-ledger.md`) で「貼られている版」を確かめる。切り替えの前に、全部を確認する |
| 7 | 切り替えの順序の間違い | 先に受付 (厳しい機械チェック) を入れ、あとで Work の指示文を変える。途中の状態は、どちらも「安全側に止まる」。各段階は、戻せる (前の版を残す) |
| 8 | Work が、承認の範囲を広く読む | 承認の「対象・操作」は、手順書 (`docs/work-ops/`) に書かれた操作の名前と一致するものだけ。手順書にない操作は、承認があっても、しない (指示文の4番は、そのまま残す) |
| 9 | 承認の本文に、秘密・URL・ID・個人データが混ざる | 受付が、URL・鍵らしい文字列・メールの形などを検出したら、断る |
| 10 | お金が増える | 新しい課金・有料の道具は使わない。定期実行は足さない。承認の原文に、お金・課金・購入などの言葉があれば、受付が断る (人に聞く) |
| 11 | 過去の依頼 (FORM-1/2 など) が、新しい決まりで、再処理される | 過去の依頼は、取消・結果ありで、受付と Work が実行しない (今のまま)。新しい決まりは、新しい依頼IDにだけ効く |
| 12 | 承認の記録を、モネが忘れる・遅れる | 承認がない依頼は、受付が断る (安全側に止まる) |
| 13 | 受付の機械チェック自体の誤作動 (正しい依頼を断る・間違った依頼を通す) | 失敗の型ごとに、再現するテストを先に書く (別の対象・使い回し・編集された承認・書式違い・お金の言葉・期限切れ・消えた承認)。テストが通るまで、Merge しない |
| 14 | 権限が広がる変更を、よしひろさんの確認なしに入れる | 受付のコード変更と、凍結を外す PR は、Codex とアムのレビューのあと、よしひろさんが Merge する |
| 15 | Work の「結果が出ない」問題 (別の未解決の問題) | この設計では直さない。原因が特定されるまで、Work は凍結のまま。解除は、`docs/approval-policy.md` の条件どおり |

## 解除後の最初の依頼 (最小の試験)
費用0円・本番なし・1件だけ・読み取りに近い小さな操作 (例: 問い合わせフォームの作成1件)。結果を確かめてから、通常に戻す。
