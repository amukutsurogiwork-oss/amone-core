# アム Chat の手順書 3/3 (3-blocked-report)

アム Chat の指示文 (第14版) が、毎回 main から取得して従う手順書。**秘密・URL・ID・個人データは書かない。** 変更は、PR と、よしひろさんの Merge (権限が広がるもの) を経る。

【止まったときの報告】
・黙って止まらない。PR #23(回答を投稿してよい唯一の場所)の未回答の相談で止まるときは、**対象が範囲外・承認が確認できない、のときも**(権限不明・読み取れない・判定不能のときは、下のとおり画面だけ)、止まる理由を、その相談スレッド(PR #23)に、1回だけ [AMU-ANSWER] request=相談ID round=同じround source=元コメント番号 status=blocked で投稿する(2026-11-12 よしひろさんの指示: 止まったら必ず返事を残す)。本文は、止まった理由の分類(範囲外 / 承認が確認できない / ログイン待ち・承認待ち)、確認できたこと、できなかったこと、次の担当だけ。相談の本文・対象の中身・非公開の値は書き写さない(検証前の依頼の文は、そのまま写さない)。この投稿は、対象のリポジトリやPRを開くための許可ではなく、読み取りの範囲は広がらない。
・**ログイン・本人確認・承認画面で進めないとき**(2026-11-12 よしひろさんの指示)も、止まった理由の分類に「ログイン待ち」または「承認待ち」と書いて、上と同じく PR #23 に status=blocked を1回出し、画面にも「どの画面で、何をすれば進むか」を1行で書く。ID・パスワード・URL などは書かない。GitHub に書けないときは画面にだけ書く(モネは時間切れで気づいて、よしひろさんに知らせる)。
・**この優先順位の条件(所有者の確認など)が適用されるのは、止まった報告(status=blocked)だけ**。通常の回答(許可された相談への [AMU-ANSWER])には、適用しない。通常の回答の投稿は、これまでの条件(台帳・許可範囲・取消・重複・直前の再照合)だけで決める。所有者の確認が取れないことを理由に、通常の回答を止めてはいけない(2026-11-12: author_association が取れず、通常の回答まで止まった)。
・**止まった報告を投稿してよい条件の優先順位**(アムの指摘 PR17-REVIEW-21): 先に、次をすべて確かめる。(1) 相談コメントを書いた人が、GitHub の実データで、リポジトリの所有者であること。確認は、コメントの user のログイン名が、台帳の repo の owner と一致することで足りる(author_association が取得できなくても、user が取れれば確認できたものとする。user も取れないときだけ、確認できないとして画面だけ)。(2) PR #23 への報告が、この文で事前に許可された操作であること(この文が許可しているのは、PR #23 への1回の status=blocked だけ)。(3) 上の確定・再照合の条件。ひとつでも満たさない・確認できないときは、画面にだけ書く。これらを満たしても、範囲外・承認未確認の対象は読まない。報告先(PR #23)の既存の権限は広げない。共用アカウントで書かれていることは、本人承認の証明に使わない。
・重複判定は、相談ID・round・source で行う。同じround の別の返信や取消も照合する。同じ相談ID・round・source の status=blocked がすでにあれば、理由が違っても、自動で重ねて投稿しない。理由が変わったときは画面で報告し、新しい相談IDでの再依頼を待つ。
・status=blocked は、回答ではない。相談を回答済みにしない。同じ元コメントへの通常の回答を、自動で許可する根拠にもならない。再依頼は、新しい相談IDで出すのを基本とする。
・複数の相談が止まったときも、GitHub への報告は、許可済みの各相談ごとに、source を明示して個別に判定する。まとめるのは画面の報告だけ。
・投稿しないのは、次のときだけ(画面にだけ書く): 台帳の検証失敗・取得失敗、権限不明、判定不能、直前の再照合の失敗、アクセス拒否のとき、取消された相談、すでに回答済みの相談、同じ相談ID・round・source の status=blocked がすでにあるとき、PR #23 を取得できない・GitHub 接続が使えない・投稿権限がないとき(投稿できないとき)、相談ID・round・source が読み取れないとき(壊れた相談)。
・**1件で止まっても、そこで全体を止めない**(2026-11-12: 古い相談を未回答と見間違えて止まり、後ろの本当の未回答に届かなかった)。ある相談で止まったら、上の止まった報告を出す(または、画面にだけ書く)ことを済ませたあと、**次の未回答の相談の処理を続ける**(最大3件の範囲で)。回答済みかどうかは、PR #23 の全コメント(最後のページまで)で、**同じ相談ID・同じ round・元コメントの番号(source)がすべて一致する** [AMU-ANSWER] を探して判定する(status=blocked は回答済みに数えない。round=2・3 の追加の相談は、前の round の回答があっても、その round の回答が付くまで未回答)。
・投稿の結果が分からないときは、既存のコメントを確認する。確認できなければ、再投稿せず、「結果不明」と画面に書いて止まる。アクセス拒否は迂回しない。
