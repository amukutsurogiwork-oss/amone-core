# Work の操作 `consult` (Work 自身の予定タスクの実行の記録を、読むだけで調べて報告する)

目的 (2026-11-16): Work の結果が出ない原因 (WORK-CAUSE-4、WORK-FIX-5) を調べるため、予定タスク「AMONE Work依頼受付(新)」の**実行の記録**を、Work 自身に読んでもらい、PR #25 に1回だけ報告してもらう。よしひろさんの手間を減らすための操作 (よしひろさんの指示「出来るだけあもねでやって欲しい」、2026-11-16)。

**範囲 (これだけ)**
- 読むのは、Work 自身の予定タスクの**実行の記録** (どの実行が、いつ、何をきっかけに始まり、どう終わったか) だけ。
- 書き込みは、PR #25 への `[AMU-RESULT] request=<ID>` の**1回だけ**。予定タスクの設定・指示文の変更、ほかの実行の起動・停止、ほかの場所への投稿、ログイン・認証の代行は、しない。費用が出る表示が出たら止まる。
- 実行の記録が読めないときは、推測で埋めず、「履歴が読めない」と1回報告して終わる。
- 承認は要らない (読み取りだけの操作)。依頼に「承認の記録」の欄は書かない。
- 秘密・URL・ID は書かない (実行を見分けるのは、時刻と、きっかけの種類で)。

## 依頼の書き方 (モネが、sandbox の専用 PR #25 に書く)
```
[MONE-REQUEST] id=<ID> lane=work op=consult sha=<PR #25 の、いまの先頭の版>
⟦AMONE-WORK⟧
手順書の版: docs/work-ops/consult.md の amone-core main の版 (コミット)
目的: 予定タスクの実行の記録の読み取り (読むだけ)
対象の時間帯 (日本時間): <時間帯の一覧>
聞きたいこと: <下の「報告」の項目>
期限: <依頼から3日以内>
報告: どんな状態で終わっても、[AMU-RESULT] request=<ID> を1回、PR #25 に書く。画面にも必ず報告する
取消: [MONE-REQUEST] id=<ID> status=cancel があれば、何もせず止まる
次の担当: アム Work
```

## 手順 (Work)
0. 依頼の全項目、取消の有無、`sha=` が PR #25 の先頭の版と同じこと、同じIDの既存の結果が無いことを確かめる。合わなければ、何も書かず終わる。
1. 着手の記録 (`[AMU-CLAIM]`) は**書かない** (PR #25 に新しいコメントを増やさないため)。
2. 予定タスク「AMONE Work依頼受付(新)」の実行の記録を、読むだけで開き、対象の時間帯の実行を、すべて調べる。
3. 終わる直前に、同じIDの取消・既存の結果をもう一度確かめ、`[AMU-RESULT] request=<ID>` を**1回だけ**書く。
4. 失敗したら、自動でやり直さない。

## 報告 (`[AMU-RESULT] request=<ID>`)
対象の時間帯の実行ごとに1行:
- 実行を見分けられる表示 (時刻など。ID・URLは書かない)
- きっかけになったコメントの種類 (依頼 / 受付Bot / 連絡コメント [MONE-NOTE] / 結果 / 不明) と、その時刻
- 開始と終了の時刻 (秒まで分かれば秒まで。分からなければ「不明」)
- 終わり方 (完了 / 何もせず終了 / 途中で止まった / 不明)
- 画面を読んだ時間帯 (本体の場合)
- ほかの実行と同時に動いていた時間があれば、その秒数
- エラー・警告があれば、その要約
あわせて: 連絡コメントと受付Bot のコメントのあとに実行が起きたか (「起きた」「無いと確認」「履歴が読めない」を分ける)。確かめた事実と推測は分ける。最後の行は「次の担当: 担当と次の作業」。
