# Work の操作 `sheet-copy-dryrun` (コピーのシートとスクリプトでの試運転)

アムの設計 (sandbox PR #23 の WORK-DRYRUN-6) を、モネが確かめて書いた。よしひろさんの承認の範囲 (2026-11-12): **国永 PR #83 の試運転のため、コピーを作って試験すること。** コピーの**削除は含まない** (削除は、結果を見てから、別に本人の承認を取る)。本番には一切触らない。
秘密・URL・ID・写真の値・ログ本文は、GitHub にもチャットにも書かない。書くのは、試験名・合否・件数・停止理由だけ。

## 依頼の書き方 (モネが、sandbox の専用 PR に書く)
```
[MONE-REQUEST] id=<ID> lane=work op=sheet-copy-dryrun sha=<この依頼を書く sandbox の PR の、いまの先頭の版 (受付が照合する)>
対象: <owner/repo> の PR #<番号> (読み取りのみ。この PR にもその repo にもコメント・変更はしない)
対象の版 (target-sha): <対象 PR の完全な head SHA 40文字。Work が照合する>
コピーの識別名: <名前。URL・IDは書かない>
期限: <日付>
承認の範囲: コピーの作成、コピーでの試験の実行、結果の報告 (削除は含まない)
取消: [MONE-REQUEST] id=<ID> status=cancel があれば、何もせず止まる
次の担当: アム Work
```
`sha=` は、依頼を書く sandbox の PR の先頭の版で、受付が照合する (対象 PR の版を入れると、受付が古い版として断る)。対象の版は `target-sha` に書き、Work が照合する。どちらかが更新されたら、自動で追わず、止まる。台帳の許可だけでは実行せず、依頼ごとに上の全項目がそろっていることを確かめる。

## 手順 (Work)
1. 依頼の全項目、取消の有無、依頼を書いた sandbox の PR の先頭の版が `sha=` と同じこと、対象 PR の head SHA が `target-sha` と同じことを確かめる。違えば止まる。
2. コピー元の所有者・共有状態を確かめる。コピー先は、よしひろさんの Drive の中だけ。共有しない。
3. コピーのシートと、**別のプロジェクト**のコピーのスクリプトを作る。
4. コピー側の外部送信・通知・時間トリガー・編集トリガー・自動実行を止める。本番を指す URL・ID・認証情報・Properties・ライブラリ・外部 API・書き込み先が残っていないか確かめる。ひとつでも本番を指していたら、止まる。
5. `target-sha` のコードだけを、コピーに入れる。参照先は、コピーのものにする。
6. 次の試験を行う。各試験の前後で、行数・日付順・対象セルの値と式・グラフの参照・サマリー・監査と重複の記録を比べる。想定外の差があれば、そこで止まる。
7. 結果 (試験名・合否・件数・停止理由だけ) を `[AMU-RESULT] request=<ID>` で書く。コピーは、削除せず、非共有のまま残す。

## 試験と合格の基準
| 試験 | 合格 |
|---|---|
| スイッチ OFF の回帰 | 従来の確定結果と同じ |
| スイッチ ON: 複数候補の順序 | 古い撮影日時から順に確定。古い観測が新しい値を上書きしない |
| 過去日: 空のセル | 空のセルだけ補う |
| 過去日: 同じ値 | 変更なし |
| 過去日: 違う値 | 何も書かず全件止まる |
| 過去日: 行の挿入 | 日別表とグラフ表の行と参照が一致。別のセルの式がずれない |
| 挿入の途中で失敗させる | 再開後に二重に挿入しない |
| 補助の関数がないコピー | 保存・再開・復旧ができる |
| 順番の門の失敗 (意図した従来動作への復帰) | 動作を記録する。順序の保証を失う場合があることを明記し、別の試験にする |

## 動かないこと・Work がしないこと
- コードの正しさ、全データの不変性、CI の結果、本番の安全性の最終判断はモネ。Work は実施と報告だけ。
- 画面で機密が見えても、転記しない。
- パスワードや認証コードが要る所では止まる。
- 新しい共有、外部送信、課金、本番の変更、コピーの削除はしない。
