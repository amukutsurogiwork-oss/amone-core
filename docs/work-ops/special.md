# 特例役「全権」の操作 `special` (ふだんは眠っている。よしひろさんの許可が出た、そのときだけ動く)

方針の本体は `docs/approval-policy.md` の「特例役『全権』」。ここは、依頼の書き方と手順だけ。
**秘密・URL・ID・個人データは、GitHub にもチャットにも書かない。**

## 動く条件 (全部そろったときだけ)
1. ふつうの操作 (台帳の他の op) では、必要なことが、できない。
2. よしひろさんが、モネの会話で、**目的・具体的な対象・操作の範囲・期限**を示した許可を出している。
3. 依頼の「承認の記録」に、その許可の**日付と原文**が、変えずに引用されている。
4. 取消・既存の結果・重複が無い。**許可IDが、`docs/special-used.md` に行があり、別の依頼で `[AMU-CLAIM]` または完了の結果 (`[AMU-RESULT]`)していない**こと (出し直しの例外は、下の「許可の使用台帳」)。同じ依頼 ID の結果が既にあれば、使い済みなので、実行しない (許可は1回限り)。
5. 期限が、依頼から3日以内で、対象が具体的であること。

## 依頼の書き方 (モネが、sandbox の専用 PR に書く)
```
[MONE-REQUEST] id=<ID> lane=work op=special sha=<この依頼を書く sandbox の PR の、いまの先頭の版>
目的: <なんのために>
対象: <具体的に。名前・種類・件数。「ぜんぶ」「など」は不可>
操作の範囲: <やってよいことだけを、箇条書きで。書いていないことは、しない>
やらないこと: <お金がかかること、ログイン・認証の代行、既存のものの変更・削除、など、この依頼で特に外すこと>
出し直し元: <出し直しのときだけ。取消済みの前の依頼ID。ふつうは書かない>
手順書の版: <docs/work-ops/special.md の、いまの main の先頭の版(コミット)。書かれていなければ、Work は、読んだ時点の main の最新を使い、停止の理由にしない>
許可ID: <モネが、許可1つにつき1つ付ける番号。例 SP-20261114-1。同じ許可の引用を、別の依頼に使い回さないための印>
期限: <日付と時刻、日本時間 (JST)。依頼から3日以内>
承認の記録: よしひろさん本人が、モネの会話で出した許可の、日付と原文を、変えずに引用する
報告: どんな状態で終わっても、[AMU-RESULT] request=<ID> を1回、GitHub に書く。画面にも、必ず報告する
取消: [MONE-REQUEST] id=<ID> status=cancel があれば、何もせず止まる
次の担当: アム Work
```

## 許可の使用台帳 `docs/special-used.md` (許可の使い回しを防ぐ)
- **許可ID の原則**: 1つの許可IDで**有効な依頼は、同時に1つだけ**。モネは、依頼を書く前に、台帳に「許可ID・依頼ID・状態 (使用中)」の行を足す。終わったら、状態を「使用済み (結果)」にする。
- 台帳は、モネ・Chat・Work が、実行の直前に、amone-core の main から取り直して読む。台帳に、その**許可ID の行が無い**依頼は、動かない。
- **出し直し (唯一の例外)**: 前の依頼が、**受付で断られた、または着手前に止まった**ことが、GitHub の記録で確認でき、かつ、前の依頼を**先に取消した** (`[MONE-REQUEST] id=<前のID> status=cancel` を書いた) ときだけ、同じ許可IDで、新しい依頼IDを、**原因を直したあとの1回だけ**出してよい。新しい依頼には、`出し直し元: <前の依頼ID>` の欄を書く。台帳の行は、依頼IDが違っていても、許可IDが同じなら、この例外の中で通る (台帳の書き換えと Merge は要らない)。
- **操作の前の予約**: Work・アムは、最初の変更の操作の前に、`[AMU-CLAIM] request=<ID> 許可ID=<許可ID>` (結果ではなく、予約だけの印。受付の「完了」の判定には数えられない) を1回書く。書いたあと、同じ許可IDの `[AMU-CLAIM]` が、自分より先に別の依頼にないか、取り直して確かめる。先にあれば、操作せず止まる。取消された依頼は、動かない。
- **使用済みの判定**: 同じ許可IDの別の依頼に、`[AMU-CLAIM]` または `完了` の結果があれば、使用済み (出し直しの例外は、`[AMU-CLAIM]` が1つも無いときだけ)。
- 2回続けて止まったら (出し直しの分も含めて)、止まって、よしひろさんに報告する。

## 手順 (Work・アム)
0. 実行前に、台帳と、この手順書の最新 (依頼に版があれば、その版) を取り直す。**依頼の「承認の記録」に、よしひろさんの許可の日付と原文が引用されていれば、それを本人の承認として使う** (許可の方針 第9・10版。Work のチャットでの再送は要らない)。依頼の全項目、取消の有無、`sha=` が先頭の版と同じこと、既存の結果が無いことを確かめる。「承認の記録」の引用が、依頼の目的・対象・範囲・期限と合っているか確かめる。合わなければ、止まって、報告する (質問は1つだけ)。
1. **お金が増える可能性**が少しでもあれば、止まる (料金・利用条件は、実行時に公式の画面で確かめる。不明なら止まる)。
2. 依頼の「操作の範囲」の中だけを、実行する。範囲の外は、気づいても、しない。気づいた危険は、止まって報告する。
2.5. **期限の確認**: 実行の開始直前と、変更を伴う操作の直前ごとに、いまの日本時間が、依頼の期限の内か確かめる。超えていたら、未完了でも、そこで止まって報告する (続きは、新しい許可で)。
3. ログイン・パスワード・認証コード・確認画面が出たら、迂回せず止まる (よしひろさんが、専用の画面で操作する)。自動の安全チェックに止められたら、迂回しない。
4. 終わったら、**すぐに眠る**: 許可は、この依頼の1回限り。続きが要るときは、新しい許可を取る。
5. 報告 (`[AMU-RESULT]` と、画面): 何をしたか (対象・操作・結果)、できなかったこと、止まった理由。確かめていないことは、「未確認」と書く。

## しないこと
- コード変更・Merge・承認の代行 (Merge は、よしひろさん本人の1タップ)。
- 失敗や結果不明のあとの、自動の再実行。
- 範囲の拡大、「良かれと思って」の追加、別の対象への適用。
- お金が増えること、認証の迂回、秘密の記載、別アカウントの作成 (全権でも、できない)。
