# Work の操作 `form-resume` (FORM-3 で途中まで作られた問い合わせフォームを、新しく作らずに、完成させる)

経緯 (2026-11-16): FORM-3 の実行で、問い合わせフォームが、タイトルと説明だけ作られた状態で止まった。アムとの相談 (WORK-FORM-FIX-20261116) に沿って、**新しいフォームを作らず**、その1件の続きだけをする専用の操作にした (全権 `special` の代用にはしない)。
**秘密・URL・ID・個人データは、GitHub にもチャットにも書かない。** 公開してよいのは、フォームの「回答用の公開リンク」だけ (`stage=verify` で1回だけ)。

## 範囲 (これだけ)
- 途中まで作られた、**既存のフォーム1件だけ**を対象にする。**新しいフォームを作らない。**
- 段階 (`stage=`) は、次の4つだけ。**1段階 = 1つの依頼**。各段階は、よしひろさんの Work の残りの試行回数を、**1回ずつ**使う。
  - `stage=read` (読み取りだけ): 変更しない。**`[AMU-CLAIM]` は書かない。**
  - `stage=questions`: 依頼に書かれた質問のうち、足りないものだけを足す。
  - `stage=settings`: 回答のコピーと、新しい回答のメール通知を、入れる。
  - `stage=verify` (読み取りだけ): 全体を確かめる。**`[AMU-CLAIM]` は書かない。**
- 共通のやらないこと: 新しいフォームの作成、削除、共有の変更、追加の費用 (有料機能・追加契約)、追加の権限、外部サービスとの連携、ログイン・パスワード・認証コードの代行、通知先メールアドレス・編集用リンク・ID・回答データの記載。

## 4回の試行の計画
① read → ② questions → ③ settings → ④ verify。**途中で失敗したら、残りの試行を、自動では使わない** (よしひろさんとモネが、次を決める)。

## 依頼の書き方 (モネが、sandbox の専用 PR に書く)
`stage=read` と `stage=verify` の依頼 (承認の記録は書かない):
```
[MONE-REQUEST] id=<ID> lane=work op=form-resume stage=<read|verify> sha=<この依頼を書く sandbox の PR の、いまの先頭の版>
⟦AMONE-WORK⟧
手順書の版: docs/work-ops/form-resume.md の amone-core main の版 (コミット)
フォームの名前: <対象のフォームの名前>
説明: <対象のフォームの説明の原文>
期限: <日付と時刻、日本時間 (JST)。依頼から3日以内>
報告: どんな状態で終わっても、[AMU-RESULT] request=<ID> を1回、GitHub に書く。画面にも必ず報告する
取消: [MONE-REQUEST] id=<ID> status=cancel があれば、何もせず止まる
次の担当: アム Work
```
`stage=questions` と `stage=settings` の依頼:
```
[MONE-REQUEST] id=<ID> lane=work op=form-resume stage=<questions|settings> sha=<この依頼を書く sandbox の PR の、いまの先頭の版>
⟦AMONE-WORK⟧
手順書の版: docs/work-ops/form-resume.md の amone-core main の版 (コミット)
フォームの名前: <対象のフォームの名前>
説明: <対象のフォームの説明の原文>
読み取りの結果: <stage=read の [AMU-RESULT] の依頼ID。対象が1件と特定された結果>
追加する質問: <questions のときだけ。1つずつ。種類(記述式・ラジオ・段落)と、必須かどうか>
期限: <日付と時刻、日本時間 (JST)。依頼から3日以内>
承認の記録: よしひろさん本人が、モネの会話で出した許可の、日付と原文を、変えずに引用する
報告: どんな状態で終わっても、[AMU-RESULT] request=<ID> を1回、GitHub に書く。画面にも必ず報告する
取消: [MONE-REQUEST] id=<ID> status=cancel があれば、何もせず止まる
次の担当: アム Work
```
**承認の記録について**: 変更する段階 (`questions`・`settings`) だけに、承認の記録が要る。`read` と `verify` は、よしひろさんの「テストの回数」の許可の範囲で、承認の記録は**要らない**。以前、承認の記録の欄を付けたら、Work が「承認待ち」で止まったので、**`read` と `verify` の依頼には、承認の記録の欄を書かない。**

## 手順 (Work)
共通 (全段階):
0. 実行前に、台帳と、この手順書の最新 (依頼に版があれば、その版) を取り直す。依頼の全項目、取消の有無、`sha=` が先頭の版と同じこと、同じIDの既存の結果が無いこと、期限内 (日本時間) を確かめる。変更する段階では、承認の記録 (日付と原文) が、依頼の範囲と合うことも確かめる。合わなければ、止まって報告 (質問は1つだけ)。
1. 費用の確認: 個人の Google アカウントの、標準の機能だけを使う。有料の表示、追加契約、料金が分からない、が1つでもあれば、止まる。
2. 変更を伴う操作の直前ごとに、期限内か、取消が無いかを、確かめる。
3. ログイン・本人確認・認証コード・確認画面が出たら、迂回せず止まる。
4. 終わりは、必ず `[AMU-RESULT] request=<ID>` を**1回だけ**。下の「報告」の5項目を入れる。

### stage=read (読み取りだけ・着手の記録なし)
1. **`[AMU-CLAIM]` は書かない。** 何も変更しない。
2. よしひろさんの Google フォームの一覧を読み、(a) 依頼の「フォームの名前」と同じ名前のフォームの数、(b) 「無題のフォーム」の数、を数える。
3. **一覧の名前と、フォームの中の題名は、別のことがある** (FORM-RESUME-2 で、名前の一致は0件、「無題のフォーム」が2件だった)。決め方:
   - (a) が**ちょうど1件**で、(b) が0件なら、それを対象にする。
   - (a) が0件で、(b) が1件以上なら、無題のフォームを**1件ずつ、読み取りだけで**開き、中の題名・説明・質問の数・作成や更新の時刻 (見えるとき) を読む。開いても**入力・保存・共有・削除はしない**。中の題名が依頼の「フォームの名前」と完全に一致し、**かつ**説明が依頼の「説明」と食い違わないものが**ちょうど1件**なら、それを対象にする。**時刻だけで決めない。**
   - それ以外 (候補が0件・2件以上・説明が食い違う・(a) と (b) の両方がある・読んでいる間に候補の数が変わった) は、止まって、数と比べた結果を報告する。
   - ほかの候補 (対象でない無題のフォーム) は、変えず・消さず、あることと、中の題名・説明・質問の数の比べた結果だけを報告する。個人情報が見えたら、GitHub に写さない。
   - 対象は、ID やリンクではなく、この決め方で毎回同じように特定する (次の段階でも、同じ決め方でやり直す)。
4. 対象が1件なら、次を報告する: タイトル、説明、質問の数、回答のコピーが入っているか、新しい回答のメール通知が入っているか、最後に編集された時刻 (見えるとき)。編集用リンク・ID・メールアドレス・回答データは書かない。

### stage=questions
1. 前提: 依頼が、`stage=read` の結果 (対象が1件と特定されたもの) を引用していること。なければ止まる。
2. 最初の変更の前に、`[AMU-CLAIM] request=<ID>` を**1回**書く (`form-create` の着手の記録を、そのまま残す。原因が分かる前に外さない、というアムの意見)。書いたあと、コメントを**取り直して**、自分より先の `[AMU-CLAIM]` (同じ依頼ID) が無いか確かめる。**先の予約があれば、何も変更せず止まって報告する。**
3. 変更の前に、もう一度、stage=read と同じ決め方で対象を特定する。**1件に特定できなければ、止まる。**
4. 依頼に書かれた質問のうち、**足りないものだけ**を足す。ほかは変えない。足したら、保存されたことを画面で確かめる。

### stage=settings
1. 前提と、`[AMU-CLAIM]` の手順は、`stage=questions` と同じ (読み取りの結果の引用、予約、対象の再特定)。
2. 回答のコピー (必要なら、メールアドレスの収集) と、よしひろさんへの新しい回答のメール通知、**だけ**を入れる。ほかは変えない。保存を、画面で確かめる。
3. **有料・料金不明の表示が出たら、止まる。**

### stage=verify (読み取りだけ・着手の記録なし)
1. **`[AMU-CLAIM]` は書かない。** 何も変更しない。
2. 対象の1件の、質問・回答のコピー・通知を、すべて確かめる。
3. **回答用の公開リンクだけ**を、結果に1回書く。

## 報告 (`[AMU-RESULT] request=<ID>`)
どの段階も、次の5項目を入れる。確かめていないことは、推測せず「未確認」と書く。
- 対象の特定 (同名の数・無題の数・1件と特定できたか)
- 変更前後 (質問の数など。読み取りだけの段階は「変更なし」)
- 保存の確認 (画面で確かめたか)
- 止まった地点 (止まらなければ「なし」)
- 未確認

## 結果が出なかったとき
`[AMU-RESULT]` が出ないときは、**自動で再実行しない。** 次の依頼は、必ず `stage=read` から (状態が変わっている可能性があるため)。出し直しの期限は、最初の依頼の期限を引き継ぎ、延長しない。
