# Work の操作 `form-create` (Google フォームを1つ作って設定し、公開リンクを報告する)

よしひろさんの指示 (2026-11-15、モネの会話): 「問い合わせ窓口完成させていきたいね」「workで作れるよね?あもねで作れるかチェックしてくれた?」。アム Chat の設計 (FORM-WORK-47) に沿って、専用の操作にした (全権 `special` の代用にはしない)。
**秘密・URL・ID・個人データは、GitHub にもチャットにも書かない。** 公開してよいのは、フォームの「回答用の公開リンク」だけ。

## 範囲 (これだけ)
- 新しい Google フォームを**1件だけ**作る (よしひろさんのアカウント)。
- 依頼に書かれた、タイトル・説明・質問・必須の設定を入れる。
- 設定: 回答者への「回答のコピー」(標準)、よしひろさんへの「新しい回答のメール通知」(標準)。
- 完了したら、**回答用の公開リンク**を、結果に1回書く。
- やらないこと: 追加の費用 (有料機能・追加契約)、追加の権限、外部サービスとの連携、既存のフォームの変更・削除・共有の変更、ログイン・パスワード・認証コードの代行、通知先メールアドレス・編集用リンク・回答データの記載。

## 依頼の書き方 (モネが、sandbox の専用 PR に書く)
```
[MONE-REQUEST] id=<ID> lane=work op=form-create sha=<この依頼を書く sandbox の PR の、いまの先頭の版>
⟦AMONE-WORK⟧
手順書の版: docs/work-ops/form-create.md の amone-core main の版 (コミット)
目的: <なんのためのフォームか>
フォームの名前: <同名のフォームが既にあれば、止まる>
タイトル/説明: <原文>
質問: <1つずつ。種類(記述式・ラジオ・段落)と、必須かどうか>
設定: 回答のコピーを回答者に送る / 新しい回答のメール通知をよしひろさんへ
やらないこと: 上の「範囲」の「やらないこと」のとおり。費用が出る表示・追加契約が要るときは止まる
期限: <日付と時刻、日本時間 (JST)。依頼から3日以内>
承認の記録: よしひろさん本人が、モネの会話で出した許可の、日付と原文を、変えずに引用する
報告: どんな状態で終わっても、[AMU-RESULT] request=<ID> を1回、GitHub に書く。画面にも必ず報告する
取消: [MONE-REQUEST] id=<ID> status=cancel があれば、何もせず止まる
次の担当: アム Work
```

## 手順 (Work)
0. 実行前に、台帳と、この手順書の最新 (依頼に版があれば、その版) を取り直す。依頼の全項目、取消の有無、`sha=` が先頭の版と同じこと、既存の結果が無いこと、期限内 (日本時間) を確かめる。「承認の記録」に、よしひろさんの許可の日付と原文があり、依頼の範囲と合うこと (**期限は、許可の文になくてよい**。2026-11-15 の指示「許可に期限つけないで」。依頼の期限は、モネが、依頼から3日以内で付ける。期限が許可の文にないことで、止まらない)。合わなければ、止まって報告 (質問は1つだけ)。
1. **費用の確認 (最初に)**: 個人の Google アカウントの、標準のフォーム・回答コピー・新しい回答の通知だけを使う。有料の表示、追加契約、料金が分からない、が1つでもあれば、止まる。
2. **同名のフォームの確認**: 既に同じ名前のフォームがあれば、**作り直さず**、止まって報告する (途中で止まった実行の続きの場合も、まず読み取りで確かめてから続ける。二重に作らない)。
3. 最初の変更の前に、`[AMU-CLAIM] request=<ID>` を1回書く。書いたあと、PR のコメントを**取り直して**、自分より先の `[AMU-CLAIM]` (同じ依頼ID) が無いか確かめる。**先の予約があれば、何も変更せず、止まって報告する** (重複起動で、同じフォームを2回作らないため)。
4. **作成の直前に**、よしひろさんのアカウントの、フォームの一覧を読み取り、(a) 同名のフォーム、(b) 名前が付いていない・「無題のフォーム」で、この依頼の予約(`[AMU-CLAIM]`)より後に作られたフォーム、が無いことを確かめる。(b) があれば、先の実行が、作成のあと、名前を付ける前に止まった可能性があるので、**作らずに止まる**(続きは、その1件を特定してから)。フォームを作る → タイトル・説明 → 質問と必須 → 回答のコピー (必要な設定: メールアドレスの収集) → 通知、の順に設定する。各段階で、できたことを、画面で確かめる。
5. 変更を伴う操作の直前ごとに、期限内か、取消が無いかを、確かめる。
6. ログイン・本人確認・認証コード・確認画面が出たら、迂回せず止まる (よしひろさんが、専用の画面で操作する)。
7. 終わったら、**回答用の公開リンク**だけを、`[AMU-RESULT] request=<ID>` に書く。作った項目と、できなかった項目を分ける。確かめていないことは「未確認」と書く。
8. すぐに眠る。許可は、この依頼の1回限り。

## 分けるかどうか
- 作成・設定・リンクの報告は、1つの依頼にまとめてよい。ただし、途中で止まったときは、止まった段階を、結果に書く。
- 再実行は、同名のフォームの確認 (手順2) と、名前なしのフォームの確認 (手順4) を、先にしてから。**作成後の状態が不明なとき (通信の切れ・タイムアウト) は、名前の不一致を「未作成」の根拠にせず**、読み取りで、作成済みかを特定できるまで、再作成しない。
