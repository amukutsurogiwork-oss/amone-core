# 問題が起きたとき: みんなで考える「原因検討」の流れ (第12版)

よしひろさんの指示 (2026-11-15、モネの会話): 「問題が起きたらみんなで考えるようにして。仕組みをまず作ろう」。
目的: 原因を、みんなの目で、確かめる。**止めずに**、並行して、進める (第14版、凍結は廃止)。実験 (試しにもう一度) は、原因の特定ではない。
秘密・URL・ID・個人データは、書かない。

## 係の名前: 原因究明改善係 (2026-11-15、よしひろさんの指示「作って」)
会社の中の、この流れを受け持つ係。新しい AI・アカウント・費用は、増やさない (役割の名前と、記録の置き場所だけを決める)。
- 係長: モネ (始める・まとめる・記録する・直しの PR を出す)。
- 独立の分析: アム Chat。直しの独立レビュー: Codex。
- 記録の置き場所: `docs/STOPS.md` (1問題につき1行、状態つき)。
- 守ること: 原因が分かるまで、分からないことを「不明」と書く。実験で原因を決めない。副作用が不明な工程だけを止め、それ以外は、続ける (`docs/approval-policy.md` 第14版の3、`docs/design/reliable-work.md`)。
- 第1号の案件: Work の2つの問題 (承認の確認の食い違い、SP-REPO-5 の結果なし)。STOPS.md に記録中。

## いつ始めるか (自動のきっかけ)
次のどれかが起きたら、**モネが、その場で**、この流れを始める (よしひろさんに頼まない)。
- アムの `[AMU-RESULT]` が、止まった・失敗の内容のとき。
- アム Chat の止まった報告 (`[AMU-ANSWER] ... status=blocked`。範囲外・権限不明・承認待ちなど)。
- `[AMONE-NORESULT]` (結果なし) の通知が出たとき。
- 受付が断った (`[AMONE-STOPPED]`)、予想外の結果、2回続けての停止。
- よしひろさんが「おかしい」と言ったとき。
始めたら、すぐに、`docs/STOPS.md` に「原因未特定」の行を足し、**凍結はしない** (第14版)。副作用が不明な工程だけを止め、読み取り・相談・原因調査は、続ける。結果の欠落は、状態を見分けて (実行中・完了・失敗・結果不明)、続きを促す (`docs/design/reliable-work.md` の C)。

## 役割 (できること・できないことは、実測で分かった範囲)
| 担当 | 原因検討での役目 | 注意 |
|---|---|---|
| モネ | 事実の収集 (記録・時刻・画面の写真)、整理、相談の起票、STOPS.md の更新、直しの PR | 推測を、事実と書かない。確認済み・未確認を分ける |
| アム Chat | 独立した分析: 仮説の穴・見落とし・別の仮説、読み取りだけの確認方法の設計 | 相談スレッドで答える。Work の内部は、見えない |
| Codex | 直しの PR (文書・コード) の独立レビュー | 質問への回答は、できない (2026-11-14 の実測: PR のレビュー以外は、環境がないと返る)。レビュー専任 |
| Work | 自分の実行の履歴・指示文の、自己申告 (よしひろさんが、Work のチャットで、質問文を貼る) | 質問は、読み取りだけ。実験はしない |
| よしひろさん | 画面でしか見えないもの (Work の指示文、実行の履歴) の写真 | 手間は、写真だけにする (お金・認証・本人にしかできないことは、これまでどおり頼む) |

## 流れ (1つの問題につき、1回ずつ、順番に)
1. **事実 (モネ)**: 起きたことを、時刻つきで、記録の出どころとともに書く。確認済み / 未確認を分ける。 **最初に、`docs/instructions-ledger.md` で、「意図した指示」と「実際に貼られている指示」の食い違いを調べる。**
2. **仮説 (モネ)**: 考えられる原因を、可能性の高い順に。それぞれ「確かめる方法 (読み取りだけ)」と「当たったら、何が見えるはず」を書く。
3. **アム Chat に相談**: 下の雛形で、`[MONE-ASK] ... op=design` を出す (起動メールは1通)。穴・別の仮説・確認方法を、独立に出してもらう。
4. **Work に、自己申告を頼む (必要なとき)**: モネが、質問文を、コピー用に用意する。よしひろさんが Work のチャットに貼り、答えの画面を見せる。質問は、「実行の履歴」「指示文のうち、承認と報告の部分」など、読み取りだけ。
5. **読み取りの確認 (モネ)**: 記録・履歴・文書の照合を、読み取りだけで行う。結果を、事実に足す。
6. **原因の判定 (モネ+アム)**: 一致する仮説を、証拠 (記録・テスト) つきで決める。決まらなければ、「不明」のまま、足りない情報と、確かめ方を書いて、次のラウンドへ (実験で補わない)。
7. **直し**: 直しは、手引き・指示文・コード・手順のどれかに入れる。**先に、再現するテストか確認**を用意する。直しの PR は、Codex の独立レビュー + アム Chat の確認を受ける。
8. **再開・続き**: 凍結は、しない。副作用を止めた工程は、状態が読み取りで証明できたときに、続ける。最初は、小さな工程から。

## アム Chat への相談の雛形 (`op=design`)
```
[MONE-ASK] id=<ID> lane=chat op=design round=1 status=open

原因検討です (設計のみ。台帳・権限・本番は変更しません)。
問題: <一言>
事実 (確認済み): <時刻つき。出どころ>
未確認: <分からないこと>
仮説 (モネ): 1) <仮説> / 確かめ方 <読み取りだけ> 2) ...
やらないこと: 状態が不明なままの、副作用のある再試行・実験
聞きたいこと: 1) 仮説の穴・見落とし 2) 別の仮説 3) 読み取りだけの確認方法 4) 直し方の案と、その試験
範囲外: お金がかかること、台帳・権限・公開設定・本番の変更。
```

## 記録
- 各ラウンドの結論は、`docs/STOPS.md` の該当の行に、1〜2行で足す (事実・原因・直し・状態)。
- 同じ原因が再発したら、直し方が足りないということ。流れを、最初から、やり直す。
