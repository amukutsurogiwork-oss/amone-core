# 許可の方針 (第10版、2026-11-14)

よしひろさんの指示 (2026-11-13、モネの会話): 「お金以外のことは全て、ここで出した許可を、そのまま使えるようにして」。「勝手に考えて、良かれと思ってするのは、どうかと思う」。

第10版の指示 (2026-11-14、モネの会話): 「基本アモネで全部やってね。僕がやった方が早くても、僕の手間がいちばんかからない方法を考えて、僕に許可だけもらう形にして。それをメインの考えにして。みんなに縛りがあるなら、特殊なパターンとして、なんでもできる役職をお互いに作っといて？基本は動かないけど、この時だけは動けるようになるとか」。

## メインの考え (第10版)
**よしひろさんの手間が、いちばん少ない方法を選ぶ。AMONE (モネ・アム・Codex) が全部やり、よしひろさんには、許可だけをもらう。**
- よしひろさんが自分でやったほうが速くても、それを第一の案にしない。AMONE がやる道を、先に探す。
- 許可は、**コピーするだけの1文** (または1タップ) で取れる形にして、聞く。聞くのは、本当に許可が要るときだけ (下の「決まり」と、特例役の条件)。
- AMONE の道が、本当に無い (ログイン・本人確認・お金など、本人にしかできない) ときだけ、よしひろさんの操作をお願いする。そのときも、操作は最短の手順にまとめる。

## 決まり
1. **許可は、モネの会話で出されたものを、そのまま使う。** よしひろさんが、モネの会話で出した指示・許可 (削除・共有・外部への送信・本番の変更も含む) は、モネが、依頼 (`[MONE-REQUEST]`) の「承認の記録」に、**日付と原文を引用して**書く。Work とアムは、それを許可として使う。**Work のチャットでの、承認の再送は、要らない。**
2. **よしひろさんが払うお金が増えることは、全面的に禁止。** (よしひろさんの指示、2026-11-14、モネの会話: 「僕が払うお金が増えることは全面的に禁止だよ」。) 課金、有料の API、有料プランの追加、購入、クレジットの消費、無料枠を超えたときの自動の従量課金、試用が終わったあとの請求、更新・継続の課金は、依頼・引用・過去の許可があっても、**実行しない**。**費用が発生するかどうか分からないときも、実行しない** (「使える」ことと「追加の費用が出ない」ことは別)。止まった理由だけを、よしひろさんに知らせる。解除できるのは、よしひろさん本人が、この方針そのものを書き換えたときだけ (個別の返事や許可では、解除されない)。費用が増えない代わりの方法があれば、それを提案する。
3. **自分の判断で、始めない。** 依頼に書かれていない操作・対象は、しない (「良かれと思って」の追加もしない)。依頼の範囲の中で、気づいた危険は、止まって報告する。
4. **対象は、具体的に。** 削除・共有・外部への送信・本番の変更は、依頼に、対象 (名前・種類・件数) が具体的に書かれているときだけ実行する。対象があいまい、または、複数に当てはまるときは、推測せず、止まって、質問を1つだけする。
5. **取消が最優先。** 取消がある・古い版・既存の結果がある依頼は、実行しない。
6. **記録は、原文のとおり。** 依頼の「承認の記録」は、よしひろさんの言葉を、変えずに引用する。引用のない依頼は、承認なしとして、読み取りだけの操作に限って実行し、それ以外は、止まって、よしひろさんの返事を待つ。

7. **想定外で止まったら、よしひろさんに聞き、答えを学習する。** この方針や台帳、`docs/approval-learned.md` にない状況で、止まる必要が出たとき (迷うとき、あいまいなとき、初めての種類の操作) は、**自分で決めず、止まって、よしひろさんに聞く** (「どの画面で、何をしてほしいか」と、コピーするだけの文を添える)。よしひろさんが答えたら、モネが、`docs/approval-learned.md` に、**状況・答え・日付・原文**を1行で記録する。次から、同じ状況は、記録のとおりにする (「頼まずに進める」か「また、頼む」か)。止まった記録そのものは、これまでどおり `docs/STOPS.md` に残す。
8. **記録は、権限を広げない。** `docs/approval-learned.md` に書けるのは、よしひろさんが、実際に答えたことだけ。モネや Work が、自分で書き足して、許可を広げることはしない。お金のことは、記録があっても、必ず止まる。

## 特例役「全権」(第10版)
モネ側にも、アム側 (Chat・Work) にも、同じ形で置く。**ふだんは動かない。決められた条件が全部そろった、そのときだけ動く。**
- **ふだん**: この方針の「決まり」と、台帳 (`collab/registry.json`) の範囲で動く。「全権」は、眠っている。
- **動く条件 (全部必要)**: (1) ふつうの範囲では、必要な操作が、できない (台帳にない操作、登録のない対象、など)。(2) よしひろさんが、モネの会話で、**目的・具体的な対象・操作の範囲・期限**を示した許可を出した。(3) 依頼 (`[MONE-REQUEST] ... op=special`) に、その許可の**日付と原文**が、変えずに引用されている。(4) 取消・既存の結果・重複が無い。
- **動けること**: 引用された**目的・対象・範囲の中で**、台帳にない操作も含めて、必要な操作ができる (新しい公開の場所を作る、設定を変える、画面を操作する、など)。
- **すぐに眠る**: 完了したとき・期限が来たとき・取消があったとき・止まったとき。許可は、**1回限り**。次に使うには、新しい許可が要る。台帳への登録や過去の許可で、「全権」を続けて動かさない。
- **全権でも、できないこと (よしひろさんの許可でも解けない)**: (a) よしひろさんが払うお金が増えること、費用が分からないこと (上の2)。(b) 自動の安全チェック・認証・拒否の迂回、ログイン・パスワード・認証コードの代行。(c) 秘密・鍵・ID・URL・個人データの、GitHub やチャットへの記載。(d) 引用に書かれていない対象・範囲への拡大 (「良かれと思って」の追加も含む)。(e) 利用停止・拒否のあとに、別のアカウントを作ること。(f) 中身を見ずに、削除・上書きすること。
- **1回限りを守る仕組み (アム POLICY-V10-42 の指摘を反映)**: 許可には、1つずつ**許可ID**を付け、`docs/special-used.md` の台帳で、使用中・使用済みを管理する (同じ許可の引用を、別の依頼に使い回せない)。同じ依頼 ID の `[AMU-RESULT]` (または報告) が既にあれば、実行しない。実行の直前と、変更を伴う操作の直前ごとに、取消・差替え・期限切れ (日本時間で、期限内か)・既存の結果・台帳の使用済みを、もう一度確かめる。期限を超えたら、未完了でも止まる。期限は、**最長3日**。対象があいまい・期限が長すぎる依頼は、止まる。同時に2つが動いて競合した場合は、先に結果を書いたほうだけが有効で、あとの1つは止まる。
- **出し直し**: 受付で断られた・着手前に止まった依頼は、許可を消費しない。前の依頼を取消したうえで、原因を直したあと、同じ許可IDで、新しい依頼IDを、1回だけ出し直してよい (台帳の書き換えは要らない。操作の前に、`started` の予約を書き、先着の1つだけが動く。詳しくは `docs/work-ops/special.md`)。
- **失敗・結果が分からないとき**: 再実行しない。止まって、報告する (原因を直したあとの再実行は、新しい許可で)。
- **全権が、もともと持たない役割の禁止は、解けない**: コード変更・Merge・承認の代行は、全権でも、しない (Merge は、よしひろさん本人の1タップ)。削除・共有・外部送信・公開は、依頼に、個別の明確な対象が書かれているときだけ。
- **記録**: 動いたら、何をしたか (対象・操作・結果) を、`[AMU-RESULT]` または報告に、1回で書く。画面への報告は、どんな状態で終わっても、必ず行う。
- **誰が動かすか**: モネ (Claude) とアム (Chat・Work) が、お互いに、この役を持つ。相手に頼むときは、依頼の `op=special` に、引用と範囲を書く。引用が合うかは、受けた側が確かめ、合わなければ止まって報告する。
- **アムの異論 (POLICY-V10-42、2026-11-14)**: 「台帳にない操作も可能な全権は、このまま採用しないでほしい。引用だけでは、実行権限を新設できない。許可の上限と矛盾する」。よしひろさんの指示 (上の第10版の指示) は、全権を作ることなので、危険を示したうえで、よしひろさんの判断を仰ぐ。アムの指摘のうち、1回限りの仕組み・最長の期限・失敗時の停止・役割上の禁止は、取り入れた。
- 台帳の `allowedOperations` と `guiOperations` に、`special` を、sandbox の登録に足した。手順は、`docs/work-ops/special.md`。

## 注意 (共用アカウントについて)
- GitHub のアカウントは、よしひろさんと AMONE で共用していて、Work は、モネの会話を見られない。そのため、依頼の引用が本物かを、Work は確かめられない。この危険は、よしひろさんの判断で、受け入れる (2026-11-13)。
- アム (独立レビュー、POLICY-V9-33) は、「引用を本人承認とみなすのは、削除・公開・外部共有・本番の変更まで通る危険がある。第9版はこのまま採用しないで」と指摘した。よしひろさんは、その危険を知ったうえで、2026-11-14 に、モネの会話で「モネで、管理するから、お金がかかること以外は、全部進めていいよ」と答えた。これを受けて、このまま採用する。ただし、アムの指摘のうち、お金の範囲 (上の2) と、学習記録が許可を広げないこと (上の8) は、取り入れた。
- この方針は、お金に関することを、緩めない。ここに書いたこと以外 (秘密・鍵・ID・個人データを GitHub やチャットに書かない、など) の安全の決まりも、変えない。
