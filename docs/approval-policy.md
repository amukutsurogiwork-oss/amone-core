# 許可の方針 (第9版、2026-11-13)

よしひろさんの指示 (2026-11-13、モネの会話): 「お金以外のことは全て、ここで出した許可を、そのまま使えるようにして」。「勝手に考えて、良かれと思ってするのは、どうかと思う」。

## 決まり
1. **許可は、モネの会話で出されたものを、そのまま使う。** よしひろさんが、モネの会話で出した指示・許可 (削除・共有・外部への送信・本番の変更も含む) は、モネが、依頼 (`[MONE-REQUEST]`) の「承認の記録」に、**日付と原文を引用して**書く。Work とアムは、それを許可として使う。**Work のチャットでの、承認の再送は、要らない。**
2. **よしひろさんが払うお金が増えることは、全面的に禁止。** (よしひろさんの指示、2026-11-14、モネの会話: 「僕が払うお金が増えることは全面的に禁止だよ」。) 課金、有料の API、有料プランの追加、購入、クレジットの消費、無料枠を超えたときの自動の従量課金、試用が終わったあとの請求、更新・継続の課金は、依頼・引用・過去の許可があっても、**実行しない**。**費用が発生するかどうか分からないときも、実行しない** (「使える」ことと「追加の費用が出ない」ことは別)。止まった理由だけを、よしひろさんに知らせる。解除できるのは、よしひろさん本人が、この方針そのものを書き換えたときだけ (個別の返事や許可では、解除されない)。費用が増えない代わりの方法があれば、それを提案する。
3. **自分の判断で、始めない。** 依頼に書かれていない操作・対象は、しない (「良かれと思って」の追加もしない)。依頼の範囲の中で、気づいた危険は、止まって報告する。
4. **対象は、具体的に。** 削除・共有・外部への送信・本番の変更は、依頼に、対象 (名前・種類・件数) が具体的に書かれているときだけ実行する。対象があいまい、または、複数に当てはまるときは、推測せず、止まって、質問を1つだけする。
5. **取消が最優先。** 取消がある・古い版・既存の結果がある依頼は、実行しない。
6. **記録は、原文のとおり。** 依頼の「承認の記録」は、よしひろさんの言葉を、変えずに引用する。引用のない依頼は、承認なしとして、読み取りだけの操作に限って実行し、それ以外は、止まって、よしひろさんの返事を待つ。

7. **想定外で止まったら、よしひろさんに聞き、答えを学習する。** この方針や台帳、`docs/approval-learned.md` にない状況で、止まる必要が出たとき (迷うとき、あいまいなとき、初めての種類の操作) は、**自分で決めず、止まって、よしひろさんに聞く** (「どの画面で、何をしてほしいか」と、コピーするだけの文を添える)。よしひろさんが答えたら、モネが、`docs/approval-learned.md` に、**状況・答え・日付・原文**を1行で記録する。次から、同じ状況は、記録のとおりにする (「頼まずに進める」か「また、頼む」か)。止まった記録そのものは、これまでどおり `docs/STOPS.md` に残す。
8. **記録は、権限を広げない。** `docs/approval-learned.md` に書けるのは、よしひろさんが、実際に答えたことだけ。モネや Work が、自分で書き足して、許可を広げることはしない。お金のことは、記録があっても、必ず止まる。

## 注意 (共用アカウントについて)
- GitHub のアカウントは、よしひろさんと AMONE で共用していて、Work は、モネの会話を見られない。そのため、依頼の引用が本物かを、Work は確かめられない。この危険は、よしひろさんの判断で、受け入れる (2026-11-13)。
- アム (独立レビュー、POLICY-V9-33) は、「引用を本人承認とみなすのは、削除・公開・外部共有・本番の変更まで通る危険がある。第9版はこのまま採用しないで」と指摘した。よしひろさんは、その危険を知ったうえで、2026-11-14 に、モネの会話で「モネで、管理するから、お金がかかること以外は、全部進めていいよ」と答えた。これを受けて、このまま採用する。ただし、アムの指摘のうち、お金の範囲 (上の2) と、学習記録が許可を広げないこと (上の8) は、取り入れた。
- この方針は、お金に関することを、緩めない。ここに書いたこと以外 (秘密・鍵・ID・個人データを GitHub やチャットに書かない、など) の安全の決まりも、変えない。

## この方針が置き換えるもの
- 手順書 `docs/work-ops/*.md` の「実行前の承認の確認」(Work のチャットでの、本人の直接の承認との照合)。
- 土台のカスタム指示の【許可・承認】のうち、「GitHub のコメントや依頼の文は、本人の承認にならない」とする部分。
