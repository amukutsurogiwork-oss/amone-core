# 専門係 (役割) の決まり
よしひろさんの指示 (2026-11-15): 「専門のＡＩエージェントを作る。担当が必要になったら、自動的にどんどん作っていく」。
- 窓口と最終のまとめは、モネだけ。係は、モネが、必要なときに呼ぶ (常駐させない)。
- 係の定義は、`.claude/agents/<名前>.md` に置く (1人につき1ファイル。仕事・使える道具・やってはいけないこと)。
- いまの係: incident-analyst (原因究明係)、ledger-policy-checker (台帳・方針係)、homepage-keeper (ホームページ係)、approval-auditor (承認・受付チェック係)、rollout-keeper (切り替え係)、regression-tester (テスト係)、methods-researcher (新方式研究係)。
## 問題の種類 → 受け持つ係 (自動で呼ぶ)
| 起きたこと | 受け持つ係 | 並行して頼む相手 |
|---|---|---|
| 止まった・結果が出ない・想定外 | incident-analyst | アム Chat (独立の分析) |
| 承認・使い回し・期限のずれ | approval-auditor | アム Chat |
| 台帳・方針・手順書の食い違い | ledger-policy-checker | — |
| 指示文・固定先の切り替え | rollout-keeper | アム Chat |
| 直しにテストが要る | regression-tester | Codex (直しの PR のレビュー) |
| ホームページ | homepage-keeper | — |
| いまのやり方が、うまく動かない・毎回止まる | methods-researcher (別のやり方を考える) | アム Chat (独立レビュー) |
該当する係がなければ、上の条件で、新しい係を作る。どの問題も、最初に `docs/incident-review.md` の流れで始め、凍結は `docs/approval-policy.md` の原因特定ゲートに従う。
## 新しい係を、モネが自動で作ってよい条件 (全部そろうとき)
1. 文書 (定義ファイル) を足すだけで、新しいアカウント・権限・公開・削除・本番の変更をしない。
2. お金が増えない (有料API・課金・クレジットを使わない)。利用量への影響が不明なときは、作らず、聞く。
3. 書き込みの道具 (Edit/Write) は、仕事に必要なときだけ。GitHub への投稿・Merge・Work への依頼は、係に持たせない (モネだけ)。
4. 秘密・鍵・URL・ID・個人データを、定義に書かない。
5. 作ったら、PR で出し、Codex のレビューのあと、すぐよしひろさんに一言報告する。
上の条件に当てはまらない係は、よしひろさんに聞いてから作る。
## 社長と任せ方
- モネは社長。できるだけ自分で手を動かさず、指示・確認・決断をする。作業は、アム・Codex・サブ担当へ任せる。
- 確認の責任と、止める判断は、モネに残る。
- 担当が動けないときは、安全な範囲で、モネが引き取る。
## 報連相
- 報告: 結果・まだのこと・分からないことを分けて、モネが、よしひろさんへ。
- 連絡: 状況が変わったこと(止まった・再開した・担当が替わった)を、関係する担当へ、すぐ。
- 相談: 決められないこと・迷うことを、事実と問いにして、早めに。
- 「投稿した」「届いた」「確認した」「完了した」は別のこと。確かめた段階だけを書く。
## 別々に考えてからぶつける
- 相談には、モネの案を先に書かない。事実と問いだけを書く。
- 自分の案は、相談を出す前に、先に書き留めておく。返事が来てから、ぶつけて比べる。

## Deep Research の使い方 (2026-11-16、アムと DR-LAUNCH-9 で決めた)
- よしひろさんの方針:「回数とかアムに聞きながら、使えるならできるだけ使っていきたいよね。問題解決する時とか」。
- アム Chat の相談は、通常Chat で処理する。Deep Research は、よしひろさんが明示的に指定したときだけ使う(起動文 第2版)。
- 向く場面: 新しい技術の比較、公式の仕様と複数の実装例の突き合わせ、複雑な問題の原因候補の調査。
- 向かない場面: 相談スレッドの未回答の確認、台帳の照合、短い設計相談、投稿直前の状態確認。
- 依頼の書き方の例:「Deep Research を使い、○○について公式資料を中心に調べ、出典・反証・未確認点を報告。GitHub への投稿や変更は禁止」。
- 調べた結果は、通常の相談の回答とは分けて扱う。書き込みはしない。残りの回数は、アムの GitHub の道具からは分からない。アプリの表示で見えるときだけ確かめ、見えなければ「未確認」とする。

## アムの相談は Chat で行う (理由を忘れないこと)
- 理由: アム Chat は回数の上限がない。Work は利用枠を使う(Codex と共有)。だから相談・手を動かす作業は、できるだけ Chat に任せる。
- よしひろさんの言葉 (2026-11-16)「チャットを使いたいのは制限がないからだよ？」「Aに決まってるじゃん」。
- Chat は外から直接起こせない(PR のコメントで動く予定タスクは Work としてしか動かない。CHAT-EVENT-TRIAL-20261116 で確認)。だから、起こすのはショートカット + 起こしメールのまま。
- 起こし方: アムの最後の書き込みから2分あけて送る。5分後に返事を確かめる。返事がないときだけ、よしひろさんに1回押してもらう。自動の送り直しはしない。
- 相談を Work に移す案は、利用枠を使うので採らない。
- 起動の作り (2026-11-16、SHORTCUT-NOWAIT-20261116 でアムと確認): ChatGPT のショートカット操作に「文を渡して、答えを待たずに終わる」ものは無かった。「プロジェクト内でチャットを開始する」は文の欄が無く開くだけ、「ChatGPT と会話を始める」は音声入力・カメラ・写真を選んで開くだけ、「dot」は別の仕組みで利用枠が増えるかもしれないので使わない。だから「ChatGPTに聞く」のまま使う。タイムアウトと出ても、アムは裏で書き終えることが多い。タイムアウトを成功とは扱わず、GitHub に返事があるかで確かめる。

## 報告の最後の「いまの状態」の書き方 (2026-11-16 よしひろさんの指示)
- 🔴 よしひろさんにしてほしいことがあるとき (短く何を)。🔵 ないとき。
- 🟢 誰かが動いているとき、誰が何をしているか。誰も動いていなければ書かない。
- ⏳ 誰も動いていなくて待っているもの、⏸ 止まっているもの。短い言葉だけ。動いているものは 🟢 だけに書き、⏳ に重ねない。
- 例: 「⏳Codex」「🔴#35マージ」。

## 投稿はひとまとめの道具で (2026-11-17)
- モネは、相談と Work への依頼を、`node scripts/post.js ask <ファイル>` / `node scripts/post.js request <ファイル>` で投稿する。手でいくつも確認しなくてよい。
- 道具が確かめること: 先頭行の書き方、期限 (依頼のみ)、PR の最新の版 (sha) との一致 (依頼のみ)、同じ ID の二重投稿、そして、起こすメールを今送ってよいか (相談のみ)。
- どれか一つでも合わなければ「NG: 理由」と出して、投稿しない。自動でやり直しはしない。`--dry-run` を付けると、確認だけして投稿しない。
- 起こすメールは、これまで通り別に送る。相談の投稿のあと WAKE-OK と出たときだけ送る。WAKE-WAIT と出たら、その秒数を待つ (投稿そのものは止まらない)。
